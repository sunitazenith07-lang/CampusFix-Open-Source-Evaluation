# Contributing to CampusFix

1. Read the student problem statement and all relevant issues before coding.
2. Create a focused branch for each fix or feature.
3. Reproduce the issue before changing code and add a regression test.
4. Run `python -m pytest -q` locally before opening a pull request.
5. Explain the change, test evidence, and known limitations in the PR description.
6. Do not remove, skip, weaken, or hard-code around the test suite.
7. Be ready to explain each change and make a small follow-up modification during the evaluation.
